# 《1978—一生》全局游戏化界面重建计划

## 结论

上一阶段完成的是“6岁季度”的垂直样板，而不是整款游戏的视觉升级。当前网页感来自全局界面模式，必须整体替换，不能继续逐个给旧卡片换颜色。

## 当前网页感来源

1. **应用外壳像移动网页**：页面中央窄列、独立网页标题、内容向下无限延伸，没有持续的游戏世界或状态 HUD。
2. **所有内容都使用同一种文章卡片**：成长、关系、年表、档案、结算只有标题和边框差别，没有玩法身份。
3. **导航只有五个文字按钮**：像网站栏目，缺少图形、选中反馈、页面切换演出和当前任务提示。
4. **信息是阅读而非操作**：属性、方向、关系和年表主要用说明文字展示，缺少可视化进度、奖励反馈、人物状态和回看动作。
5. **事件和结算像报告页**：没有入场、悬念、结果揭示、数值跳动、奖励汇总或下一步节奏。
6. **标题与创建人生没有世界观入口**：开局只是说明文和表单，未让玩家感到“进入一生”。
7. **调试面板占据主画面**：开发阶段必要，但应变为可收起的开发者抽屉，不能持续破坏游戏视图。
8. **视觉层级过平**：缺少场景层、人物层、功能层、HUD层和弹层之间的明确空间关系。

## 统一游戏界面系统

### 游戏壳

- 全屏移动端舞台，桌面端以独立游戏窗口呈现。
- 每个主页面拥有场景横幅/背景，不再从纯色纸张开始。
- 顶部 HUD 固定显示年份、年龄、季度、阶段、核心状态和当前主线。
- 底部功能舱用统一图标、短标签和动效反馈，不使用纯文字网站导航。
- 调试功能折叠为独立开发者抽屉。

### 通用组件

- `SceneHeader`：场景图、章节、任务与当前提示。
- `GamePanel`：半透明游戏面板，按功能拥有明确层级，而不是所有卡片一个样式。
- `StatOrb` / `ProgressTrack`：属性与成长进度。
- `CharacterCard`：人物头像、关系等级、最近记忆和可进入动作。
- `ActionCard`：画面、时间/现金成本、预期收益、锁定原因、选择反馈。
- `RewardBurst`：属性、兴趣、关系与解锁的逐项结果演出。
- `GameModal`：事件、人物详情、年度结算等阻断式流程。
- `Toast / QuestUpdate`：主线推进、关系变化、自动保存和新解锁反馈。

## 各页面改造

### 1. 标题页

- 时代街景/家庭窗景主画面与标题动画。
- “开始新人生”“继续人生”作为游戏主菜单。
- 已完成的人生变成可浏览的“人生陈列柜”，不再是普通列表。

### 2. 创建人生

- 出生年份以时间胶片/年代节点选择。
- 生死模式与说明变成规则卡。
- 确认后使用镜头推进与出生揭示进入游戏。

### 3. 人生主页

- 6岁样板扩展为各年龄阶段均可使用的动态舞台。
- 行动池成为可切换、可筛选的游戏卡组。
- 当前主线、处境与季度进度收进 HUD/任务抽屉，不再堆成长文章。

### 4. 成长页

- 五项属性改为仪表/徽记，最近变化有数值动画。
- 人生方向改为多条成长路线图。
- 兴趣与成长线以技能树、等级和解锁目标呈现。
- 历史因果可展开，但默认保持游戏信息密度。

### 5. 关系页

- 从姓名列表升级为“关系圈/人物卡组”。
- 人物卡有头像、关系等级、当前生活状态、最近共同经历。
- 进入人物后展示共同记忆时间线和未来可触发关系事件。

### 6. 年表页

- 改为可拖动/可折叠的人生轨迹地图。
- 自然年仍是主轴，季度详情作为节点弹层。
- 重大事件、时代背景、关系和成长使用不同节点类型。

### 7. 档案页

- 改为“人生手册/存档舱”，展示身份、当前生涯、资产、家庭和设置。
- 删除人生等危险操作进入单独确认弹层。
- 多周目陈列与未走路线成为可回看的收藏内容。

### 8. 随机/主线事件

- 使用全屏场景、人物或物件插画、事件标题入场。
- 选项卡明确收益、代价与条件；选择后先演出再结算。
- 主线事件显示过去哪些行为让事件发生。

### 9. 季度与年度结算

- 季度：场景回放、行动回顾、属性/兴趣/关系逐项出现、随机事件提示。
- 年度：四季轨迹、年度高光、生活账本、主线推进和下一年入口。
- 使用短节奏分步揭示，避免一次展示完整报告。

### 10. 人物详情与人生结局

- 人物详情作为角色界面而不是档案文章。
- 结局使用人生蒙太奇、章节回顾、关键选择、未走路线和周目奖励。

## 动效规范

- 页面切换 260–420ms，使用场景交叉淡化与面板位移。
- 数值变化有计数与正负反馈，但同屏最多三组同时动画。
- 事件选择先锁定卡片，再进行 500–800ms 场景反应，随后进入结果。
- 只使用 transform/opacity/Canvas 位图合成，避免移动端昂贵滤镜。
- 支持 `prefers-reduced-motion`，不可见页面停止 Canvas。

## 技术边界

- 保留当前 simulation/application/presenter 数据与存档协议。
- UI 通过现有 view model 渲染，不在视觉层复制规则。
- 新游戏壳、组件和动画拆为独立模块；后续可迁移到 Vue/Capacitor 或原生容器。
- 现有 DOM 路由先保持兼容，逐页替换，确保每批修改均可回归。

## 分批交付

1. 全局游戏壳、HUD、导航、动效与调试抽屉。
2. 标题/创建人生/人生主页。
3. 成长/关系/年表/档案。
4. 事件/季度与年度结算/人物/结局。
5. 全流程浏览器、视觉、性能和响应式验证。

## 完成标准

- 任意主要页面截图都能被识别为同一款游戏，而非数据网站。
- 每个页面至少包含一种与其职责对应的游戏交互或反馈。
- 390×844 与桌面游戏窗口无横向溢出、无导航遮挡。
- 核心行动、事件、结算、存档、调试和所有人生阶段回归通过。
- 浏览器无 page error；降低动画设置有效；视觉 QA 无未解决 P0/P1/P2。
