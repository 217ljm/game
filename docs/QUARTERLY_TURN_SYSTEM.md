# 季度人生回合系统

## 核心节奏

每个自然年固定分为四个季度，每季度按约 13 周计算：

`第一季度 → 第二季度 → 第三季度 → 第四季度 → 年度结算 → 年龄 +1`

季度计划只分配上学、工作、睡眠和既定家庭义务以外的主动时间，不代表角色一年只活动几个小时。一个季度可以同时选择多项具体活动；未分配时间明确保留给休息、发呆、临时玩耍和无法逐项建模的普通生活。界面显示每周投入和约 13 周的季度总投入；教育、收入、住房、健康和家庭现金仍按自然年结算。

## 固定责任与主动休息

12 格首先根据现实事实形成固定责任明细。幼儿记录睡眠、进食、清洁与被照护；在校角色记录上课、作业与通学；就业角色读取当前岗位形成工作、排班与通勤；已有子女或年长父母时记录相应照护。剩余格才是玩家可以安排的时间，系统不保存“家庭负担中等”之类预设等级。

3 岁以后行动池固定提供“主动休息”。休息占用时间格但不消耗精力，按投入强度恢复精力并降低疲劳和压力。没有选择主动休息时，未分配时间仍代表普通生活和基础恢复，两者不是同一个奖励强度。

## 三个月内部执行

季度计划使用 `quarter-months-v1` 派生协议拆成三个确定性月份：

- 尝试一次只落在一个由独立种子确定的月份；
- 定期进行平均分布在三个月；
- 重点投入在第二个月达到最高投入，并在前后月份持续；
- 每个月分别保存行动、计划份额、实际份额、时间格、可用精力、消耗、恢复、透支、固定责任与一句过程反馈；
- 同一种子、年份、季度和计划必定得到相同月份分布。

天气、伤势和疾病等带 `interruption` 的事件发生在确定月份。事件选择可以改变剩余月份的完成率、精力、疲劳和压力；事件发生以前已经完成的投入不会被倒扣。季度结算保存计划格数、实际格数、完成率和事件月份，属性、兴趣、儿童成长时数与长期经验只按实际完成部分增长。

“维持到年底”和“只在不可执行时提醒我”每季度都会重新校验行动、时间、现金和精力。计划失效时停止自动推进，向玩家展示具体失败原因并要求重新安排，不会崩溃或静默替换人生选择。

## 不同人生阶段的操作量

| 年龄 | 主动安排季度 | 普通年份季度选择 | 含年度结算的基础交互 |
| --- | --- | ---: | ---: |
| 0 岁 | 无玩家行动；四季度自动记录感知经历 | 0 | 1 |
| 1 岁 | Q3，只选一个眼前反应 | 1 | 2 |
| 2 岁 | Q1、Q3，每次只选一个眼前反应 | 2 | 3 |
| 3～5 岁 | Q1、Q3，每季可组合 1～3 项 | 2 | 3 |
| 6～11 岁 | Q1、Q3，每季组合 2～3 项 | 2 | 3 |
| 12～59 岁 | Q1、Q2、Q3、Q4 | 4 | 5 |
| 60 岁以后 | Q1、Q3，生活安排连续两个季度 | 2 | 3 |

升学、离校、求职、换岗、伴侣、孩子、住房、照护和退休等关键事件仍会单独打断，因此关键年份可能多 1～2 次选择。年龄只在年度结算确认后增加一岁。

## 当前年龄行动池

每次主动安排先按年龄、年份、人生阶段、教育与工作状态、每周可支配时间、家庭现金、既有兴趣及成长经历生成候选池。界面一次展示最多6项，可按类别筛选并“换一批”；这些控件只翻阅确定的候选列表，不重新抽取事件，也不会清除已经勾选的行动。

行动卡展示的是潜在影响，包括季度属性积累、按计划时数估算的兴趣增长、儿童成长线和解锁条件。它不是保证值：结算仍读取实际投入时间、健康不适、临时打断和人物互动，再把本季度真正发生的变化展示在结果页。

## 控制点击量

从同年第二次主动安排开始，除重新选择行动外还提供：

- `延续上季度安排`：只延续当前季度，下季度仍询问；
- `维持到年底，除非发生关键事件`：余下普通季度快速结算；
- `只在计划不可执行时提醒我`：跨年延续，遇到阶段变化、行动条件失效或关键年龄节点才重新询问。

自动延续的季度不是被跳过：它仍保存活动数组、每周时间、约 13 周总时数、未分配时间、现金成本、影响摘要和自动推进来源。自然年表默认按年折叠，展开后可以查看四条季度明细。

## 兴趣、爱好与随机事件

每项活动带有一个或多个兴趣领域。实际季度投入会立即累积为接触时数和兴趣分数，并依次形成“偶尔接触、兴趣萌芽、稳定爱好、长期爱好”；年末只负责汇总和对长期没有投入的兴趣进行淡化。达到兴趣萌芽后，后续季度会出现“继续投入已有兴趣”的活动，不会凭空给角色贴爱好标签。

3 岁以后每季度按年龄概率至多抽取一个随机生活事件。候选还会读取人生阶段、自然年份、教育、工作、家庭和本季活动类别，并带冷却年数。事件随机流独立于计划自动选择，因此玩家点击顺序不会重抽事件；选择和后果保存在事实、兴趣记录、未选道路和存档中。

## 效果与账本

每个季度结算时立即保存实际属性变化、尚未凑满整数点的属性进度、兴趣变化、成长线变化、节点和人物关系影响。小幅属性影响采用季度残差累计，达到整数点时才改变可见属性，既让玩家看见行为正在积累，又避免把旧版一年一次的影响放大四倍。四个季度完成后再形成年度行动汇总；现金成本也按季度计入后汇总到本年账本。长期回响仍按“发生过该倾向的自然年”累计，不把四个季度误算成四年。

同一年可以安排多组不同活动；年度摘要显示实际发生过的活动。长期回响会读取每个季度计划中的全部活动，不会只把耗时最多的一项算作这一年。完整季度数组保存在年度记录的 `quarterRecords`。

## 存档协议

当前存档已由全面优化规范升级为 schema v5；以下 v4 字段仍作为兼容输入保留，并在加载时迁移为带行动强度、时间格和精力预算的 v5 季度计划：

- `quarterPlans["quarter:1984:Q1"]` 保存活动 ID 数组与控制模式；
- `quarterAutomation` 保存“只在不可执行时提醒”的跨年计划；
- `randomEventChoices` 保存条件化随机事件回应；
- `yearReviews["review:1978"]` 保存年度结算确认；
- 五阶段关键事件继续保存在 `choices`。

v4 计划会补齐默认 `regular` 投入和资源分配；v3 的单活动季度选择会迁移为单元素活动数组；v2 的 `annual:<year>` 行动先复制到四个季度；v1 也会依次补齐旧结构。浏览器活动存档键为 `people-life:active:v5`，并兼容读取 v4、v3、v2、v1 键。

## 自动化验收

`npm run foundation:check` 校验事实责任、三个月确定性、主动休息和事件中断；`npm run annual:check` 校验季度键、年龄操作量、兴趣领域、年代娱乐和随机事件内容；`npm run engine:check` 完整走一生，检查三个月记录、多活动计划、计划失效提醒、季度即时成长、随机事件、跨年自动推进、v1～v5 存档迁移和确定性回放；`npm run browser:check` 在 390×844 与 1280×900 的真实浏览器中验证场景行动条、强度选择、三个月轨道、强制发热中断、事件后果和无横向溢出。
