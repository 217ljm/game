# 《1978—一生》全面优化开发规范 v2.0

状态：**正式开发基线（A～G 首轮实现与验收完成）**  
生效日期：2026-08-23  
适用范围：模拟核心、内容数据、Web 客户端、调试工具、自动测试、TapTap H5 首发版本  
开发总目标：将现有原型升级为以季度行动、终身统一人物属性、场景行动条、长期成长因果和真实社会生活为核心的全人生模拟游戏。

## 0. 文档权威与变更边界

本文件是下一轮全面优化的主规范。若与旧文档冲突，以本文件为准；未发生冲突的技术约束继续沿用旧文档。

以下旧决策被本规范替代：

1. 玩家正式回合由“月回合”统一为“季度大回合、月内模拟”；
2. 人物属性不再使用年龄校准或同龄百分位，终身使用同一套 0～100 绝对数值；
3. 主玩法不再依赖场景点击热点，也不再展开大批文字行动卡；
4. 旧纸、褐色、低饱和剪贴簿不再是 UI 主视觉，年代感改由场景内容表达；
5. 原“五项属性”升级为六项终身核心属性，心情改为短期状态，关系改为人物之间的数据；
6. 季度计划由单纯活动 ID 数组升级为带投入强度、时间格、精力、延续模式和实际结算的计划。

继续保留：

- `docs/TECHNICAL_ARCHITECTURE.md` 的确定性模拟、分层依赖、增量状态机、内容包、IndexedDB 与渐进迁移原则；
- `docs/LIFE_MAINLINE_SYSTEM.md` 的非固定成功路线、七个人生章节与一生回顾原则；
- `docs/SOCIAL_SIMULATION_MODEL.md` 的事实型社会状态与历史校准边界；
- 现有出生、童年、教育、青少年、初入社会、成年模拟与调试脚本，在迁移完成前保持兼容。

## 1. 产品定义

### 1.1 主题

玩家从改革开放初期出生，在家庭、地区、教育、职业、关系、住房、健康和时代变化中，通过一个个具体行动逐渐成为一个具体的人。

人生本身就是主线。游戏不把考大学、发财、买房、结婚或属性全满设为唯一通关目标。

### 1.2 核心体验

玩家应持续感受到：

1. 我正在安排这个角色真实可支配的生活；
2. 我本季度做的事情在人物、关系和环境中留下了可见痕迹；
3. 早年的选择会在多年后改变可进入的生活；
4. 社会条件会限制机会，但不会替玩家决定结局；
5. 没有走过的道路能够在年表和结局中回看；
6. 不同周目可以在同一时代形成明显不同的人生。

### 1.3 非目标

- 不制作实时 3D 开放世界；
- 不要求逐日安排吃饭、睡觉等常规行为；
- 不用一次选择直接增加大量核心属性；
- 不用长篇文字代替全部行动反馈；
- 不设置唯一总分或完美人生；
- MVP 不引入联网后端、排行榜、支付或强制账号。

## 2. 人生时间与季度回合

### 2.1 时间尺度

- 1 个正式玩家回合 = 1 个自然季度；
- 1 个季度内部依次模拟 3 个月；
- 1 年 = 4 个季度回合 + 1 次年度总结；
- 年龄在出生月份经过时增加，界面可显示“X 岁 Y 个月”；
- 关键事件可以在月内打断季度计划，但不凭空增加时间；
- 活到 80 岁最多约 320 个正式回合。

目标节奏：

- 普通季度 30～60 秒；
- 关键季度 1～3 分钟；
- 第一段完整人生约 6～10 小时；
- 自动延续和快速结算可显著缩短二周目。

### 2.2 季度阶段

每个季度固定经过：

1. `quarter.prepare`：生成固定责任、时间预算、精力与候选行动；
2. `quarter.plan`：玩家在场景中安排 2～4 项主要行动；
3. `month.resolve × 3`：按月结算持续行为、人物回应和事件；
4. `event.choose`：仅在关键事件发生时阻断；
5. `quarter.review`：展示实际投入和有意义的变化；
6. `quarter.continue`：重新计划、延续一季、延续到年底或延续到失效。

### 2.3 十二个生活时间格

每季度固定有 12 个生活时间格，表示三个月内能够稳定安排的生活空间，不等于精确小时。

固定责任先占用时间格：

| 状态 | 典型占用 |
| --- | ---: |
| 婴幼儿基本生活与照护 | 6～9 |
| 小学 | 5～6 |
| 中学 | 6～7 |
| 全日制学习 | 6～8 |
| 全职工作 | 6～8 |
| 兼职 | 2～4 |
| 照顾孩子/病人 | 1～4 |
| 通勤 | 0～2 |

系统保存具体义务与来源，不保存“时间紧张：中等”这类标签。

### 2.4 体能、精力与时间的边界

- `fitness` 体能：人物终身核心属性，0～100，不在季度开始时重置；
- `quarterEnergy` 精力：本季度可消耗资源，每季度按状态重新计算；
- `timeSlots` 时间格：季度计划容量，每季度重新分配。

三者不得复用字段、图标或文案。

### 2.5 季度精力

基础精力为 10，最终限制在 4～16：

```text
季度精力 = 10
         + 健康修正
         + 心情修正
         + 作息修正
         - 疾病与伤势
         - 高强度工作、通勤与照护负担
```

推荐第一版修正：

| 条件 | 修正 |
| --- | ---: |
| 健康 ≥ 85 | +2 |
| 健康 70～84 | +1 |
| 健康 50～69 | 0 |
| 健康 30～49 | -2 |
| 健康 < 30 | -4 |
| 心情 ≥ 80 | +1 |
| 心情 20～39 | -1 |
| 心情 < 20 | -2 |
| 规律作息 | +1 |
| 轻微疾病 | -1 |
| 严重疾病/伤势 | -2～-4 |
| 高负担工作或照护 | -1～-3 |

体能主要改变运动、劳动、远行等体力行动的实际消耗、成功率、恢复和受伤风险，不应显著改变阅读或普通交流的消耗。

### 2.6 行动强度

| 强度 | 时间格 | 典型精力 | 语义 |
| --- | ---: | ---: | --- |
| `trial` 尝试一次 | 1 | 1～2 | 接触、体验或完成一次事件 |
| `regular` 定期进行 | 2～3 | 3～4 | 在季度内形成规律投入 |
| `focus` 重点投入 | 4～5 | 5～7 | 作为本季度主要方向 |

一次选择代表一段持续安排。例如“定期踢球”代表本季度持续参与，不要求玩家为每次踢球重复点击。

### 2.7 休息、留白与透支

- 休息 1 格：恢复 2 精力；
- 较长休息 2 格：恢复 3 精力并改善心情；
- 未分配时间在季度末转为恢复、普通生活和临时活动；
- 最多允许透支 3 精力；
- 每透支 1 点增加疲劳、失败、疾病和受伤风险；
- 连续两季度透支形成持续疲劳；
- 严重疲劳会锁定高强度行动。

## 3. 终身人物模型

### 3.1 六项核心属性

所有核心属性使用终身统一的 0～100 绝对数值：

| ID | 中文 | 定义 |
| --- | --- | --- |
| `health` | 健康 | 疾病、伤势、睡眠、营养与身体完整状态 |
| `fitness` | 体能 | 实际力量、耐力、灵活和协调能力 |
| `intelligence` | 智力 | 已形成的理解、记忆、逻辑、专注和创造能力 |
| `appearance` | 外表 | 五官、体态、气色、整洁和穿着形成的整体印象 |
| `social` | 社交 | 表达、共情、观察和处理人际关系的能力 |
| `willpower` | 意志 | 自律、韧性、自信和承受压力的能力 |

不得再输出“同龄优秀”“年龄校准后 70”等值。

### 3.2 出生初值

普通足月、无严重疾病的第一版参考范围：

- 健康 75～95；
- 体能 1～4；
- 智力 1～3；
- 外表基础 35～65；
- 社交 0～2；
- 意志 1～4。

早产、难产、孕期营养、遗传与医疗条件可以改变范围。健康描述当前身体状态，因此可以在出生时较高；其余能力按实际尚未发育的绝对能力保持较低。

### 3.3 短期状态

以下数据不是永久能力：

- `mood` 心情；
- `stress` 压力；
- `fatigue` 疲劳；
- `quarterEnergy` 本季度精力；
- 疾病、伤势与临时自信；
- 当前饥饿、营养或睡眠问题。

旧“心情”从核心属性迁移为状态；旧“关系”迁移为人物之间的关系记录。

### 3.4 子属性

- 健康：免疫、睡眠、营养、疾病、伤势、慢性问题；
- 体能：力量、耐力、灵活、协调、恢复；
- 智力：理解、记忆、逻辑、专注、创造、空间能力；
- 外表：基础外貌、体态、气色、整洁、穿着适配、年龄/伤痕；
- 社交：表达、共情、观察、分寸、说服、关系维护；
- 意志：自律、韧性、自信、情绪稳定、独立性。

### 3.5 成长经验

核心属性不因普通单次点击直接 `+1`。行动先积累残差经验：

```text
成长经验 = 行动基础经验
         × 投入强度
         × 连续性
         × 环境条件
         × 当前状态
         × 隐藏潜力效率
         × 边际递减
```

达到阈值后属性增加 1 点；属性越高，下一点所需经验越多。隐藏潜力只影响效率和可达范围，不作为出生时的职业或性格标签展示。

健康允许因疾病、伤势、治疗和恢复直接变化。体能和部分技能会因长期不使用、衰老或疾病下降。年龄影响成长与衰退速度，但不改变数值标尺。

### 3.6 兴趣、习惯与技能

兴趣阶段：

`尚未接触 → 有过接触 → 兴趣萌芽 → 稳定兴趣 → 长期爱好`

兴趣领域至少覆盖阅读、数学、绘画、音乐、运动、机械、自然、表达、社交、烹饪、交易和公共事务。

技能来自实践，不由智力直接替代。习惯来自跨季度重复行为，包括作息、阅读、锻炼、储蓄、整洁、拖延、冒险、逃避和主动交往。

## 4. 场景与行动系统

### 4.1 场景定位

场景回答“我在哪里、谁在这里、发生了什么”，负责气氛和反馈，不负责让玩家寻找点击热点。

基础场景：家庭、邻里、学校、操场/公园、商店/市场、工作地点、医院、文化娱乐、交通旅行、亲友住所和公共服务场所。

场景随地区、年代、季节和人生阶段改变。

### 4.2 行动条

场景下方一次显示 3～5 个行动条项目。每项默认只显示：

- 图标与行动名称；
- 时间格、精力和金钱成本；
- 2～4 个潜在影响图标；
- 风险等级；
- 是否可以持续执行。

详细条件放入轻量抽屉，不在主界面铺开长段落。完整候选池使用紧凑图标网格或分类切换，不使用无限下拉的文章卡片。

### 4.3 行动候选生成

候选必须读取：年龄、自然年份、人生阶段、场景、季节、天气、资金、六项属性、状态、兴趣、技能、人物关系、教育/工作、时代条件、近期行为、事件、冷却和重复惩罚。

生成后列表固定。“换一批”只翻阅已生成列表，不重新抽事件或结果。

### 4.4 第一人称年龄行动

- 0～2 岁：观察、模仿、伸手、表达需求、移动、接近、探索；
- 3～5 岁：游戏、启蒙、交友、尝试兴趣、帮助家人；
- 6～11 岁：学习、娱乐、运动、同伴、家庭责任；
- 12～17 岁：学习方向、同伴、兴趣、兼职准备与独立；
- 18～24 岁：教育、求职、工作、居住、关系与社会入口；
- 25～39 岁：事业、家庭、住房、育儿、财富和自我发展；
- 40～59 岁：责任、健康、职业变化、照护与重新选择；
- 60 岁以后：健康、家庭、兴趣、社会参与、传承与晚年生活。

幼年选项必须是角色自身可做的反应和行动，照看者的安排只能作为环境与事件条件。

## 5. 行动反馈与长期因果

每项行动至少产生四层表现：

1. 操作反馈：按压、选中、资源扣除、进入计划轨道；
2. 过程反馈：角色动作、NPC 回应、场景局部变化、月份推进；
3. 即时反馈：一句结果、状态、关系、资金和风险变化；
4. 长期反馈：兴趣、习惯、技能、属性残差、解锁和后续事件。

结果必须可解释。例如：

> 你连续三个季度参加跑步，耐力训练开始形成。体能 42 → 43。

领域事实由模拟核心先结算并保存，动画、声音、震动只表现结果，不能决定结果。

### 5.1 事件

事件分为日常、人物、机会、危机、时代和人生节点。普通季度最多出现 1 个需要回应的随机事件；关键节点可以中断计划。同类事件有冷却，多个事件按优先级排队。

后果分为即时、中期和长期。重大转折必须能回溯到角色状态、人物关系、社会事实或过去行动，不允许无因出现。

## 6. 社会现实模型

家庭、教育和职业只保存事实：

- 父母/角色职业、单位、合同、工时和工资；
- 家庭人口、住房、储蓄、债务、教育/医疗支出；
- 地区、学校、费用、教师、班级和政策；
- 行业、单位性质、工作年限、技能和经济环境；
- 自然年份对应的物价、工资、住房、教育和就业条件。

“收入稳定性”“教育资源”等结论由上述事实动态推导，不作为出生时预设标签。

历史观测放入 `data/calibration/` 并保留来源；虚构人物、行动与事件属于 gameplay；未来情景和设计假设必须明确标识。

## 7. 页面与交互架构

### 7.1 五个主页面

1. **场景**：当前环境、季度状态、人物和行动条；
2. **地图**：地点、交通、开放条件、人物和机会；
3. **人物**：六项属性、状态、兴趣、习惯、技能、外表、物品、学业/职业；
4. **关系**：家庭、朋友、同学、老师、同事、伴侣、子女及共同记忆；
5. **记录**：自然年主轴、季度详情、时代背景、关键选择、未走道路和多周目。

标题、创建人生、出生揭示、事件、季度结算、年度总结、章节回顾、结局、人生画廊和设置属于流程页或弹层，不占用主导航。

### 7.2 移动主界面

390×844 为首要视口：

- 顶部 HUD：年份、年龄、季度、精力、时间和金钱；
- 中部场景：人物、NPC、环境和轻量动画；
- 下部行动区：3～5 个行动条；
- 底部导航：不高于约 56～64px 的五个入口。

主玩法页面不得依赖整页纵向滚动。调试面板收进可关闭的开发者抽屉。

## 8. 视觉、动效与声音

### 8.1 配色

- 主蓝 `#4DA8FF`；
- 青绿 `#35CDB4`；
- 珊瑚 `#FF7066`；
- 明黄 `#FFC857`；
- 活力紫 `#8878F6`；
- 深色文字 `#24304A`；
- 浅背景 `#F6F9FC`；
- 风险红 `#E84D5B`。

年代感来自建筑、服装、发型、商品、交通、学校、单位、海报和环境声音，不使用整屏褐色、低饱和纸张或木质控制台。

### 8.2 动效预算

- 按钮 120～180ms；
- 行动条展开 180～280ms；
- 页面切换 260～420ms；
- 行动结果 400～800ms；
- 季度/年份推进 600～900ms；
- 氛围循环 4～12 秒且幅度极小。

优先使用 `transform`、`opacity` 和 Web Animations API；支持关闭、减少和完整三档动画。声音与触感也必须可关闭。

## 9. 技术与数据协议

目标技术栈继续使用 TypeScript、Vite、Vue 3、Hash 路由、纯 TypeScript 确定性核心、Web Worker、IndexedDB、JSON Schema、SVG/WebP/CSS 动画与 TapTap H5 适配。当前原生 ESM 代码采用渐进迁移，不一次性重写。

必须支持 v1～v4 迁移，不能静默重抽已经发生的人生事实。

## 10. 调试与质量门槛

- 终身属性不做年龄归一化；

- 资源不足、休息、透支和疲劳；

- 事件打断与确定性随机；
- 兴趣、习惯、技能和关系记忆；
- 社会事实筛选；
- v1～v4 存档迁移；
- 390×844 无横向溢出；
- 动画关闭、素材失败和刷新恢复后仍完整可玩。

## 12. 总体验收

只有同时满足以下条件才算完成本规范：

- 玩家明确理解一回合为一个季度；
- 普通季度通常只安排 2～4 项行动；
- 六项属性终身使用同一绝对标准；
- 早期行为确实影响智力、体能、健康、兴趣、习惯和关系；
- 场景一次只推出少量相关行动；
- 每项行动拥有过程、结果与长期回响；
- 社会结论由具体职业、收入、地区、政策和家庭事实产生；
- UI 鲜活、现代、有游戏反馈且主页面不依赖长篇文字卡；
- 没有唯一成功人生，未选道路可回看；
- 完整人生可确定性回放，旧存档可迁移；
- 模拟、UI、浏览器和发布检查全部通过。
