# 可玩版本说明

## 启动

项目没有运行时依赖。安装 Node.js 18 或更高版本后，在项目目录执行：

```powershell
npm run play
```

浏览器打开 `http://127.0.0.1:4173`。服务只监听本机 `127.0.0.1`，按 `Ctrl+C` 停止。

## 页面结构

运行中的人生使用同一个 HTML 应用壳和 hash 路由，内容被拆成五个常驻主页面：

- **人生**：当前年份、年龄、季度进度、现实处境和本次可执行选择；
- **成长**：五项属性、兴趣、成长路径、事实和本年账本；
- **关系**：当前共同生活的家人，以及后续出现的同学、朋友、老师、伴侣与孩子；
- **年表**：按自然年汇总的人生记录，季度明细按需展开；
- **档案**：出生信息、当前节点、种子、自动保存状态、历史人生与返回标题入口。

标题、创建人生、随机事件、季度结果、年度结算、人物详情和人生结局使用独立流程页。流程页隐藏底部导航，避免玩家在必须回应的事件或结算中误离开。当前路由写入 URL，正式存档仍只保存模拟选择；刷新主页面或人物详情时，会从 v4 存档重放并恢复到对应页面。

## 一局怎样进行

1. 选择 1978～1982 年中的出生年份，或让系统随机决定。
2. 决定是否包含按历史校准的幼年生存风险。
3. “人生”页显示当前人生章节，以及眼下要维持、正在积累和想要靠近的三条课题。课题读取实际健康、教育、工作、关系、住房、账本、兴趣和成长记录，不预设唯一成功路线。
4. 0 岁不替照护者作决定，四季度自动记录喂养、睡眠、声音、光线和触碰等第一人称经历；1～2 岁从当前年龄的行动池中回应眼前能看到、听到和够到的事物。
5. 行动池读取年龄、年份、人生阶段、现实状态、时间与现金、既有兴趣和成长经历。界面一次展示最多 6 项，支持分类筛选和“换一批”；翻页只改变展示，不会重抽随机结果或丢失已经选择的行动。
6. 每张行动卡先展示它推进的人生课题或方向，以及属性积累、兴趣倾向、成长线和未满足的解锁条件。3 岁以后可在同一季度组合具体活动；学龄后通常选 2～4 项，活动时间之和不能超过本阶段每周可主动安排时间；未分配时间保留给休息、发呆、临时玩耍和普通生活。
7. 结算页立即列出这次实际改变：整数属性变化、尚在积累的属性进度、兴趣分数、成长线节点与人物关系；健康或生活打断可能让实际结果低于卡片预览。成长页保留最近行动及其影响来源。
8. 1 岁在 Q3、2～11 岁在 Q1/Q3、12～59 岁每季度、60 岁以后在 Q1/Q3 主动安排。后续可延续上季度、维持到年底，或只在计划不可执行时提醒。
9. 同岁的条件化随机事件，以及升学、求职、关系、住房等关键事件会额外打断；四季度完成后查看兴趣、家庭、教育、工作、健康、财务和三条人生课题的自然年汇总。
10. 确认“年度结算”后年龄只增加 1，进入下一岁；同学、朋友等虚构人物可以跨年保留。每个人生章节结束时，会形成由实际行动、属性变化、支出和关键事件组成的章节回顾。
11. 结局查看一生守住与放下的方向，以及五项属性、教育、工作、关系、住房、资产、兴趣、未来情景年份、未选路径和完整自然年表；每年可以展开季度明细。

界面中的“历史观测范围”表示当前年份不晚于 2025 年；“2026 年后情景”表示经济和结构参数来自中性延伸情景，不是已经发生的事实，也不是预测。

## 存档与复现

游戏在每次选择后把版本化存档写入浏览器 `localStorage`，当前键为 `people-life:active:v5`。如果发现旧键 `people-life:active:v4`、`people-life:active:v3`、`people-life:active:v2` 或 `people-life:active:v1`，会读取、迁移并在下一次自动保存后移除旧键。存档只保存：

- `schemaVersion`；
- 随机种子；
- 可选的固定出生年份；
- 是否启用幼年生存风险；
- 五个人生阶段的事件 ID → 选项 ID 映射。
- 按自然年和季度保存的多活动计划、随机事件回应，以及可选的跨年自动延续设置；
- 已经确认过的年度结算。

模拟结果不直接写入存档，而是每次根据种子与选择从出生重放。因此同一份 JSON 存档会精确复现同一档案、每个年度事实和最终结局，也避免部分计算状态升级后难以修复。最近 20 个结局的标题、年龄、种子和代表性未选道路另存于 `people-life:gallery:v1`；下一局开始前会显示“那一生没有走”的路径，形成跨局发现。

## 代码入口

- `public/index.html`：移动端应用壳、五个主页面与流程页面结构；
- `public/styles.css`：纸张、印章和五项属性的移动端视觉；
- `public/app.mjs`：页面渲染、流程协调、自动存档、调试界面与结局画廊；
- `public/browser-platform.mjs`：浏览器存储、随机种子、滚动和下载适配；
- `src/app/routes.mjs`：页面路由、主页面和流程页面边界；
- `src/game/game-application.mjs`：创建、恢复和提交选择的游戏命令；
- `src/game/page-presenter.mjs`：五个主页面及流程页的视图模型；
- `src/game/game-engine.mjs`：五阶段编排、等待选择和存档校验；
- `src/game/presenter.mjs`：把模拟事实转成人可读文本；
- `src/game/load-game-data.mjs`：浏览器端加载所有校准与内容配置；
- `scripts/serve-game.mjs`：无依赖本地静态服务。

运行 `npm run engine:check` 可验证跨阶段手动选择、未选分支、JSON 存档往返、确定性回放、自动完整人生、早逝结局和事实年表。运行 `npm run ui:check` 可验证页面元素与脚本引用、全部数据文件、移动端布局约束、键盘焦点、减少动效设置和本地 HTTP 资源。

在安装了 Edge/Chrome 和 Playwright 的开发环境中，运行 `npm run browser:check` 会以 390×844 竖屏和 1280×900 桌面视口真实打开页面，验证标题与创建人生、年龄行动池、分类筛选与换一批、行动影响预览、季度实际变化、成长来源、年度结算、五个主页面、人物详情与返回、路由刷新恢复、正式/调试存档隔离，以及强制随机事件流程；回归截图写入 `artifacts/ui-regression`。Codex 桌面运行时已包含所需 Playwright；其他环境可用 `PEOPLE_LIFE_PLAYWRIGHT_PATH` 和 `PEOPLE_LIFE_BROWSER_PATH` 指定路径。

## 发布前仍需做什么

本版本用于验证核心体验。正式发布前仍需按目标平台完成构建适配、触摸真机测试、低端机性能测试、内容和敏感词审核、隐私与用户协议、软著与平台主体资质、统计与崩溃监控。平台 SDK、广告和支付不应进入第一轮核心玩法验证。

开发阶段需要快速到达指定年龄、季度或关键事件时，使用独立的 [人生调试台](DEBUGGING.md)，不要修改正式存档里的年龄字段。3～12岁分龄活动、过程结果、成长线、人物记忆和解锁规则见 [3～12岁完整玩法纵向切片](CHILDHOOD_PLAY_SYSTEM.md)。
