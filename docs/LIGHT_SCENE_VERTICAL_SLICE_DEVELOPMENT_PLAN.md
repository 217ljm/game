## 0. 制作人结论

《1978—一生》不制作类似大型生活 RPG 的自由移动地图，也不让玩家控制角色在大量房间、街区和道路中反复走路。

正式产品形态定义为：

> **舞台式轻场景人生模拟**：每次进入一幅有人物、物件、环境状态和时间压力的生活画面；玩家点击人物或物件，完成一个短动作或微互动，看见现场与关系发生变化，再把结果带入季度和一生。

“移动”只用于连接生活片段，不作为核心操作：

```text
院门 → 院中空地 → 石桌 → 家门 → 屋内
```

玩家点击节点后，通过 0.6～1.5 秒镜头切换、角色换位、环境音变化和一句不超过 18 字的过场完成移动，例如：

> 铃声散了，你沿着院墙回家。

这类短句只负责连接时间和空间，不负责替代场景、动作与反馈。

### 三条不可违背的产品边界

1. **不做开放地图**：无摇杆、无持续寻路、无大面积空走、无为了点击对象而走几十秒。
2. **不做文字行动墙**：主场景不展开全部行动卡，不让文字同时承担地点、动作、结果、数值和背景解释。
3. **不做假场景**：一张背景图加缩放不算场景；人物、物件、热点、状态变化、动作、声音和结果反馈必须各自存在。

## 1. 市场参考与组合方向

本项目不照搬任何一款产品，而是组合几种已被市场验证的轻量表达方式。

| 参考产品 | 已验证的形式 | 本项目借鉴 | 明确不照搬 |
| --- | --- | --- | --- |
| [我的孩子：生命之泉](https://www.taptap.cn/app/801402) | 固定家庭场景、日常时间安排、烹饪/手工/陪伴等具体行为影响人物 | “固定生活空间＋人物状态＋时间安排＋可见情绪反馈” | 战争创伤主题、单一照护者视角和较重资源压力 |
| [Florence](https://www.taptap.cn/app/66514) | 用一系列短小游戏表现调情、争吵、互助和关系变化 | 让互动动作本身表达感情和生活，而不是结果报告 | 线性短篇结构；本项目必须支持长期模拟和多路径 |
| [往事](https://www.taptap.cn/app/232679) | 固定手绘场景、点击互动、低对白叙事 | 可见对象、短点击/拖动行为、音乐与场景状态承载叙事 | 以解谜为核心和两小时内的线性流程 |
| [Unpacking](https://www.unpackinggame.com/) | 房间作为关卡，物件与摆放讲述多年人生 | 用生活物件表现年代、家庭和人生变化 | 不把本项目变成收纳游戏 |
| [中国式家长](https://www.taptap.cn/app/234747) | 年龄阶段、日程、成长形象和主题小游戏组织人生 | 年龄节点、季度安排和少量关键玩法模块 | 重复训练、全屏数值刷取和大量同构点击 |
| [青春叙曲 Growing Up](https://www.taptap.cn/app/802619/all-info) | 日程、技能、城市节点、朋友关系和成长小游戏 | 时间规划、阶段解锁、人物共同成长 | 直接复制其庞大活动量和美国 90 年代内容 |
| [众生](https://www.taptap.cn/app/808921) | 低成本角色与物件也能让人生发生在画面中 | 接受简洁美术，但必须让人物和物件真正参与玩法 | 横向扩张过多生活系统和场景 |

推荐组合公式：

```text
《我的孩子》的固定生活场景
＋《Florence》的短互动演出
＋《往事》的点击对象
＋《Unpacking》的物件叙事
＋《中国式家长》/《Growing Up》的年龄与时间结构
```

该组合不是视觉模仿，而是制作规模和交互职责的参考。

## 2. 首个切片的玩家体验目标

### 2.1 一句话体验

> 1984 年初秋，6 岁的你放学回到家属院，在天黑前的一小段自由时间里，第一次决定要和谁相处、做什么，以及如何面对一个意外。

### 2.2 目标时长

- 首次完整体验：10～12 分钟；
- 第二次尝试不同选择：5～8 分钟；
- 玩家输入：约 8～14 次有意义输入，不计算跳过与设置；
- 长段正文阅读：0 次；
- 可展开记录：场景结束后提供，不阻塞游玩。

### 2.3 玩家应获得的感觉

切片结束后，玩家应能自然说出：

- “我刚才在扮演这个孩子”；
- “我选择了和谁在一起、做了什么”；
- “人物或环境对我有反应”；
- “如果重来，我想试试另一件事”；
- “这件小事以后可能还会留下影响”。

如果玩家只能说“我选了几个选项，属性涨了”，切片视为失败。

## 3. 核心循环

```text
进入生活片段
→ 看见人物、物件和当前状态
→ 点击一个明确对象
→ 就地出现 2～3 个短动词
→ 完成 2～8 秒动作/微互动
→ 人物、物件、时间和环境立即回应
→ 选择继续、停止或转向另一个对象
→ 关键事件打断
→ 现场余波＋季度长期结果
```

### 3.1 玩家点击什么

玩家点击的是：

- 人：伙伴、照护者、年长孩子；
- 物：书包、弹珠、碗筷、自行车链条；
- 地点状态：院门有人喊、屋里传来叫声、天色变暗；
- 情境动作：加入、帮助、练习、询问、停止。

玩家不点击：

- “学习类”“家庭类”“娱乐类”等抽象分类；
- 十几张同时展开的行动卡；
- 写着完整结果预测的报告按钮；
- 为了移动而存在的方向键和摇杆。

### 3.2 一次行动的最低结构

每项行动必须具备：

```text
对象状态 → 玩家意图 → 可见过程 → NPC/物件回应
→ 当场代价 → 局面变化 → 长期事实候选
```

任何只有“点击按钮→显示一段结果”的行动不得进入切片。

## 4. 时间、回合、体力与季度

### 4.1 三级时间结构

| 层级 | 游戏时间 | 玩家操作量 | 作用 |
| --- | --- | --- | --- |
| 人生层 | 1 年 = 4 个季度 | 每年约 4～8 次核心决定 | 维持一生节奏、时代与年龄变化 |
| 季度层 | 3 个月 | 安排 2～4 项持续行动，处理 0～2 个关键事件 | 决定长期投入、责任与现实限制 |
| 生活片段 | 某个月的一次代表性场景 | 5～12 分钟、3～5 个具体行动 | 提供参与感、人物与物件反馈 |

不是每个月都制作完整 10 分钟场景。一个普通季度由：

- 1 个重点可玩生活片段；
- 2 个 5～15 秒月份蒙太奇；
- 必要时 1 个短关键事件；
- 1 个不超过 30 秒的季度余波。

幼年可由家庭安排两个季度连续执行；无重要变化的成年季度也可自动延续。只有真正影响玩家计划的变化才要求重新选择。

### 4.2 首切片的时间资源

- 场景时间：放学后 45 分钟；
- 表现为 9 个可视时间格，每格约 5 分钟；
- 每项主要行动消耗 2～4 格；
- 转场消耗 0～1 格，不让玩家因点击场景节点受到无意义惩罚；
- 天色、远处声音、照护者呼唤和 HUD 同时表达时间变化；
- 玩家可以提前停止一项行动，保留部分体验和不同人物反应。

### 4.3 体力与短期精力

- 健康、体能继续使用全人生统一的 0～100 标准，不因年龄重置；
- 当前片段消耗的是短期精力，不把长期体能当行动点直接扣除；
- 专注不是新终身属性，由心情、疲劳、健康、兴趣和环境干扰派生；
- 行动按钮只显示时间、精力和必要现金图标，不预告 `智力 +0.37`；
- 长期影响由 Core 结算并进入记录，场景只用趋势图标和人物回应表现。

### 4.4 季度投入不再使用表单

行动强度改成场景内的“安排印记”：

- 1 枚：试试看；
- 2 枚：每周做；
- 3 枚：这季重点。

玩家先在场景中真实体验这项行为，再决定是否把它安排进本季度。不能在还没看见行为前让玩家填写强度。

## 5. 场景结构与移动表达

### 5.1 三个连续舞台

| 舞台 | 时长 | 主要作用 | 对象 |
| --- | ---: | --- | --- |
| A. 院门 | 1～2 分钟 | 建立处境、时间压力与人物邀请 | 伙伴、照护者呼唤、书包、院门 |
| B. 院中 | 5～7 分钟 | 主要自由选择与动态事件 | 石桌、弹珠空地、自行车棚、伙伴、年长孩子 |
| C. 家中 | 2～3 分钟 | 让过去选择产生可见余波 | 碗筷、照护者、脏衣/作业/找到的弹珠 |

这不是三张独立网页，而是同一个 SceneRuntime 中的三个舞台状态。

### 5.2 节点式移动

玩家点击“空地”“石桌”“家门”等节点时：

1. 当前对象退出焦点；
2. 主角播放 2～4 帧换位或短走动；
3. 镜头做轻微平移/推近；
4. 环境音交叉淡化；
5. 必要时显示一句不超过 18 字的过场；
6. 新舞台的对象进入可互动状态。

不实现：

- 角色连续寻路；
- 碰撞地图；
- 大地图探索；
- 虚拟摇杆；
- 玩家在空场景中寻找隐藏热点；
- 因走错路浪费现实时间。

### 5.3 可发现对象

每个舞台只显示 3～5 个对象。所有对象必须具备：

- 可读名称；
- 可见状态或轻动画；
- 触摸热区；
- 键盘焦点；
- 当前可用/忙碌/锁定反馈；
- 无障碍对象列表中的等价入口；
- 2～3 个与该对象有关的短动词。

## 6. 首切片内容规格

### 6.1 人物

| 人物 | 当下目标 | 可见状态 | 会记住什么 |
| --- | --- | --- | --- |
| 主角 | 在回家前决定如何使用自由时间 | 期待、犹豫、疲劳、弄脏、开心/失落 | 自己做过的行动、成功/失败、是否坚持 |
| 同龄伙伴 | 想让主角加入弹珠游戏 | 招呼、等待、投入、着急 | 是否被回应、是否得到帮助、共同结果 |
| 年长孩子 | 在自行车棚摆弄链条 | 专注、不耐烦、愿意解释 | 主角是否礼貌询问、是否乱动、是否帮忙 |
| 照护者 | 希望主角按时回家并做一点家务 | 忙碌、提醒、认可/担心 | 是否守时、是否帮忙、衣服和作业状态 |

### 6.2 四项主行动

| 行动 | 触发 | 微互动/演出 | 可见回应 | 长期事实候选 |
| --- | --- | --- | --- | --- |
| 加入弹珠 | 点击伙伴/空地 | 单次瞄准与释放；不做复杂胜负系统 | 弹珠滚动、伙伴表情与站位改变 | 身体节律、同伴关系、玩耍兴趣、弄脏风险 |
| 练一会字 | 点击石桌/书包 | 描一笔或选择继续/停下；避免识字考试 | 纸页变化、角色坐姿、旁人评价 | 理解求知、学校适应、专注习惯、错过邀请 |
| 看看自行车 | 点击车棚/年长孩子 | 转动脚踏、询问或直接触碰 | 车轮/链条动作、手上油污、年长孩子反应 | 动手兴趣、认知、关系、轻微受伤风险 |
| 帮忙摆碗 | 点击家门/照护者 | 拖放 2～3 件碗筷 | 桌面逐步完成、照护者姿态和语气改变 | 家庭参与、责任习惯、关系、自由时间减少 |

每个微互动只服务一次意义表达，不制作可刷分的无限小游戏。

### 6.3 动态事件

事件：一颗弹珠滚到自行车棚附近。

演出顺序：

1. 弹珠从空地滚出；
2. 伙伴停止动作、寻找并表现焦急；
3. 年长孩子因车棚被打扰作出反应；
4. 场景出现与当前对象相关的短行为：帮忙找、问年长孩子、继续原行动、回家；
5. 结果改变弹珠位置、人物站位、表情、剩余时间和后续对白；
6. Core 写入关系、风险与经历事实。

事件不得弹出整页文章，也不展示全部精确收益与风险。

### 6.4 三类结局状态

切片不设置传统输赢，只形成三类可混合的余波：

- **同伴记忆**：和伙伴共同完成或处理了事情；
- **兴趣萌芽**：识字、动手或身体活动首次产生可追踪兴趣；
- **家庭印象**：照护者对守时、帮忙和主动表达形成不同记忆。

玩家可以同时获得两类，也可能因为犹豫而只留下普通的一天。普通不是失败，但必须让玩家理解机会已经过去。

## 7. 文本、UI、动画与声音规范

### 7.1 文本预算

| 内容 | 上限 |
| --- | ---: |
| 节点名称 | 2～5 字 |
| 行动按钮 | 2～7 字 |
| 即时气泡 | 24 字，最多 2 行 |
| 场景过场 | 18 字，显示约 1～2 秒 |
| 动态事件提示 | 36 字 |
| 普通季度结算正文 | 80 字 |
| 详细因果 | 仅记录页展开 |

文字用途：短对白、内心、时间连接和关键因果收束。  
文字禁用用途：代替动作、代替场景、罗列所有数值、解释玩家刚刚已经看见的事情。

### 7.2 390×844 界面层级

```text
┌──────────────────────┐
│ 1984 / 6岁 / 初秋  ◉◉◉ │  轻 HUD
├──────────────────────┤
│                      │
│    舞台式生活场景      │
│ 人物 / 物件 / 环境状态  │  约占 72%
│  局部气泡 / 结果图标    │
│                      │
├──────────────────────┤
│ 当前对象：加入 / 看看   │  情境动作条
└──────────────────────┘
```

- 游玩中隐藏原五栏底部导航；
- 角色、关系、记录、设置从暂停层进入；
- 主舞台不允许纵向滚动；
- 情境动作条一次最多 3 项；
- 精确账本不占据主舞台；
- 当前可行动对象必须在 3 秒内可辨认。

### 7.3 最小动画清单

主角：待机、转向、短换位、观察、坐下写字、蹲下玩、拿起/放下、高兴、失落。  
NPC：待机、招呼、交谈、邀请、寻找、认可/不认可。  
物件：弹珠滚动、门开关、碗筷摆放、纸页变化、车轮/链条转动。  
环境：树叶/衣物轻动、傍晚光色、远处人影或声音变化。

### 7.4 动效原则

- 点击 100ms 内出现压感、焦点或声音；
- 一次完整短演出 2～6 秒；
- 镜头焦点放大不超过 1.08 倍；
- 动画表现已结算事实，不决定事实；
- 支持完整、减少、关闭三档；
- 关闭动画后操作仍可完成；
- 不以持续漂移、卡片飞入和数字跳动充当角色动画。

## 8. 技术架构与引擎 Spike

### 8.1 为什么不立即全面迁移 Phaser

用户明确要求的不是自由移动、大地图、碰撞和寻路。Phaser 仍然能提供 Scene、显示列表、摄像机、输入、Loader、Tween、动画和音频，但首切片未必需要为这些能力承担完整迁移成本。

反过来，继续在当前 `app.mjs` 和 Presenter 中堆绝对定位元素也会再次变成网页。轻方案必须是独立的游戏场景运行时，不是旧页面的新皮肤。

因此第一技术阶段不是争论，而是制作同规格的双 Spike。

### 8.2 候选 A：DOM SceneRuntime

```text
SceneRuntime
├─ StageController          舞台状态与转场
├─ ActorLayer               人物精灵与姿态
├─ PropLayer                物件状态
├─ HotspotLayer             原生按钮、焦点与触摸热区
├─ CueDirector              WAAPI 演出队列
├─ AudioDirector            环境与短音效
├─ ContextActionBar         情境动作条
└─ AccessibleObjectList     等价对象列表
```

要求：

- 不进入旧 Presenter；
- 不生成滚动卡片；
- 人物、物件和热点是状态化对象；
- 使用 CSS 精灵表、`transform/opacity` 与 Web Animations API；
- 原生按钮承担键盘、焦点和无障碍语义；
- 模拟 Core 通过稳定契约接入。

### 8.3 候选 B：Phaser SceneRuntime

```text
Phaser Scene
├─ Background / Foreground Containers
├─ Actor / NPC GameObjects
├─ Prop GameObjects
├─ Hotspot Input Zones
├─ Camera Focus Director
├─ Animation / Tween / Sound
└─ DOM Overlay for HUD and Accessibility
```

要求：

- 只实现固定舞台和节点换位，不加入物理、碰撞和寻路；
- HUD、记录和无障碍对象列表仍可使用 DOM；
- 通过同一个 `SceneRuntimePort` 读取 Cue；
- 不把 Phaser Scene 变成模拟规则容器。

Phaser能力依据：[官方 Scene 文档](https://docs.phaser.io/phaser/concepts/scenes)、[官方动画文档](https://docs.phaser.io/phaser/concepts/animations)。

### 8.4 不进入 Spike 的方案

- 原生 Canvas：既缺少 DOM 可访问性，又需要自行维护命中、场景树、动画、资源和音频；
- PixiJS：渲染能力优秀，但 Scene、音频、输入语义和玩法协议仍需自行补齐；只有 DOM 和 Phaser 都不能满足时再评估。参考：[PixiJS 架构](https://pixijs.com/8.x/guides/concepts/architecture)。

### 8.5 一天双 Spike 范围

两个版本使用同一份临时素材和同一组行为：

- 1 幅院中灰盒背景；
- 主角、伙伴、石桌和弹珠 4 个对象；
- 4 个节点；
- 2 段动作：走向伙伴并蹲下、弹珠滚动并使伙伴反应；
- 1 次焦点转场；
- 1 条短对白；
- 1 个情境动作条；
- 390×844 与桌面窗口；
- 触摸、键盘和减少动态模式。

### 8.6 技术选型评分

| 指标 | 权重 | 必须通过 |
| --- | ---: | --- |
| 场景感、角色层级和动作连续性 | 25 | 是 |
| 新增人物/物件/舞台的维护成本 | 20 | 是 |
| 与确定性 Core 和 Cue 的隔离 | 15 | 是 |
| 390×844 性能与资源体积 | 15 | 是 |
| 触摸、键盘与无障碍替代入口 | 15 | 是 |
| 构建、调试和发布复杂度 | 10 | 否 |

决策规则：

- 任一方案未通过前五项硬门槛则淘汰；
- 两者都通过且总分差小于 10 分，选择 DOM SceneRuntime，控制个人开发复杂度；
- Phaser 高出至少 10 分，或 DOM 无法稳定维护人物/动作/焦点层级，则选 Phaser；
- 选型一旦冻结，首切片期间不得再次摇摆。

| 叙事/关卡设计 | GPT-5.6-terra | 舞台脚本、NPC 动机、事件、短对白 | 必须服从文本预算和玩法边界 |

| 美术/动效导演 | GPT-5.6-terra | 角色比例、分层场景、精灵表、镜头与动效清单 | 概念稿不能直接宣称正式资产 |
| 内容实施工程 | GPT-5.6-sol | 运行时、演出、命令接入和存档恢复 | 只实现已冻结规格 |
| QA/试玩研究 | GPT-5.6-luna | 自动检查、试玩脚本、观察记录和报告 | 不以自动化结果替代玩家体验 |

### 10.1 并行批次

```text
批次 A：玩法导演 / 叙事关卡 / 客户端架构
                     ↓ 主代理冻结 G0
批次 B：UI交互 / 美术动效 / QA测试设计
                     ↓ 主代理冻结 G1
批次 C：客户端实施 / 内容接入 / 自动回归
                     ↓ 主代理形成可玩构建
批次 D：盲测分析 / 缺陷修复 / 性能与发布检查
```

不能并行：

- 动词、时间规则和 SceneRuntime 契约未冻结前，不做正式 UI 和最终美术；
- Spike 未完成前，不迁移完整客户端；
- 灰盒不好玩前，不批量生成背景、角色和行动；
- 5～8 人盲测未通过前，不扩展到 18 岁；
- 20～30 人封闭测试未通过前，不公开测试或制作商店宣传。

### 10.2 多代理文件纪律

- 每名实施代理只负责明确文件或模块，禁止多人同时修改同一文件；
- 代理先提交设计/补丁摘要，由主代理检查后合并；
- 稳定 ID、协议和规则由主代理维护唯一版本；
- 子代理不能自行增加依赖、改存档版本或扩展需求；
- 所有生成素材保留来源、版本和用途，概念稿与实机资产分开；
- 当前工作区没有 Git 元数据，正式多代理编码前必须先建立可恢复的版本快照或版本控制，避免并行覆盖。

## 12. 盲测规模与方法

### 12.1 第一轮：5～8 人探索性盲测

这是当前切片应采用的规模。目的不是证明市场规模或留存，而是尽快暴露：

- 玩家是否知道能点谁、点什么；
- 是否认为自己在参与生活；
- 动作和反馈是否比文字更先被感知；
- 是否自然产生“我想试另一种做法”的念头；
- 是否仍然把产品称为网页、PPT 或文章。

招募建议：

- 4～5 名普通手机游戏玩家；
- 2 名叙事/模拟类玩家；
- 1 名不常玩游戏的人；
- 排除开发者、已读本文档的人和会主动照顾评价的熟人。

每人单独测试 30～40 分钟：

1. 10～12 分钟无提示试玩；
2. 5 分钟复述刚才发生了什么以及为什么选择；
3. 5～8 分钟重玩或尝试另一条路线；
4. 完成 1～7 分问卷和三个开放问题；
5. 经同意记录屏幕、点击、停顿、误触和主动提问。

通过门槛：

| 指标 | 标准 |
| --- | ---: |
| 无提示找到第一次行动 | 至少 6 人，中位时间 ≤45 秒 |
| 完成“对象—动作—反馈”闭环 | 至少 6 人 |
| 能说出一个可见后果 | 至少 5 人 |
| “我在控制孩子生活” | 7 分量表平均 ≥5 |
| “像网页/PPT/文字卡” | 7 分量表平均 ≤2.5 |
| 愿意继续下一个生活片段 | 至少 6 人 |
| 阻断流程严重问题 | 0 个未修复 |

样本只有 5 人时，人数门槛按 4/5、4/5、4/5、4/5 相应缩放，不对百分比作市场推断。

### 12.2 第二轮：20～30 人封闭测试

只在第一轮通过并修订后进行，持续 3～7 天，验证：

- 多设备与不同屏幕；
- 重玩与第二路线尝试；
- 操作理解差异；
- 基本完成率和继续意愿；
- 存档恢复、性能和内容节奏。

通过门槛：

| 指标 | 标准 |
| --- | ---: |
| 无协助完成首片段 | ≥80% |
| 首次行动中位时间 | ≤40 秒 |
| 正常完成率 | ≥75% |
| 主动重玩/尝试第二行为 | ≥45% |
| “选择有意义、结果能理解” | ≥4.8/7 |
| “画面与反馈让我愿意继续” | ≥4.5/7 |
| “像网页/PPT/阅读器” | ≤2.5/7 |
| 崩溃、丢档、卡死 | 0 个未修复 |

### 12.3 公开测试

不是当前阶段。至少在第二个 18 岁切片完成、20～30 人封闭测试通过后，才进行 100～300 人受控公开试玩。公开测试之前不购买流量、不大范围宣传、不把首切片当成完整产品。

### 12.4 固定问卷

1～7 分：

1. 我感觉自己是在控制一个孩子的生活，而不是阅读选项；
2. 我通常知道此刻能和谁或什么互动；
3. 我能理解我的行动为什么带来了这个结果；
4. 场景里的角色、物件和变化让我想继续观察；
5. 我愿意再玩一个新的生活片段；
6. 这个体验像网页、PPT 或信息卡片（反向题）；
7. 如果在 TapTap 看到这段实机视频，我愿意下载试玩。

开放题：

- 你记住的第一个画面或动作是什么？
- 哪一刻你觉得自己真的在参与？
- 哪一刻你觉得自己只是在读或点菜单？

## 13. 技术与产品完成标准

### 13.1 产品标准

- 新玩家进入后 60 秒内完成第一次具体行为；
- 玩家在场景中停留的时间 ≥75%；
- 至少发现 3 个对象并完成 2 个不同动词；
- 每次主要行动都有角色或物件状态变化；
- 至少一次 NPC 主动行为和一次动态事件；
- 一次季度余波正文 ≤80 字；
- 不看数值面板也能理解自己做了什么、影响了谁；
- 场景结束后明确产生一次重玩或下一片段动机。

### 13.2 技术标准

- 390×844 主舞台无滚动、无导航遮挡、无横向溢出；
- 点击后 100ms 内有视觉或声音响应；
- 一次短演出可跳过且不改变 Core 结果；
- 完整/减少/关闭三档动画均可完成流程；
- 资源加载失败有降级状态，不能出现空白舞台；
- 刷新恢复后人物、物件与已发生事实一致；
- 同种子、内容版本和命令序列仍产生相同结果；
- 控制台无错误，触摸、键盘和等价对象列表可用；
- 中端移动设备目标 60fps，压力状态稳定不低于 30fps。

### 13.3 停止标准

出现以下任一结果时，停止扩张并回炉：

- 盲测多数玩家仍先阅读文字而不是观察场景；
- 玩家不知道对象能否互动；
- 动作前后人物和世界没有可见区别；
- 需要主持人解释才能完成第一行为；
- UI 为容纳信息重新开始纵向滚动；
- 为了一个小场景已经需要大量一次性美术和代码；
- 代理为追求“完整”擅自扩展到其他年龄、地点或系统。

## 14. 粗略工作量与范围控制

个人学生开发、AI 辅助、无固定全职美术团队的量级估计：

| 阶段 | 量级 |
| --- | --- |
| 双技术 Spike 与选型 | 1～3 个开发日 |
| 三舞台灰盒与 Core 接口 | 2～4 周 |
| UI、角色、场景、动作、声音完成首切片 | 4～8 周 |
| 5～8 人测试与一轮修订 | 1～2 周 |
| 第二个 18 岁切片 | 3～6 周 |
| 多关键年龄公开测试版 | 6～12 个月 |

如果工期超出，按以下顺序缩减：

1. 减少一次性动作种类；
2. 减少 NPC 数；
3. 减少舞台状态；
4. 减少分支演出；
5. 保留长期结果但复用表现模板。

不得通过以下方式缩减：

- 把动作过程重新写成结果段落；
- 把所有对象变回行动卡；
- 删除人物回应；
- 用静态背景替代状态化场景；
- 省略首次玩家测试。

## 15. 开发启动前检查单

项目负责人确认以下七项后，才进入 T0：

- [ ] 认可“舞台式轻场景”，不做大地图自由移动；
- [ ] 认可移动采用节点转场、短动画和极短文字；
- [ ] 认可主场景每次只显示 3～5 个对象和 2～3 个情境动词；
- [ ] 认可首切片只做 6 岁放学后 10～12 分钟；
- [ ] 认可先进行 DOM SceneRuntime / Phaser 一天双 Spike；
- [ ] 认可第一轮只做 5～8 人小范围盲测；
- [ ] 认可盲测不过就不扩展到 18 岁和全人生。

确认后，主代理按批次 A 启动玩法、叙事和架构代理；双 Spike 选型冻结后，再启动 UI、美术、实施和 QA 代理。
